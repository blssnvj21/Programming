🗺️ The complete programming map
ZERO → ADVANCED
This is the long-term syllabus—not a claim that one tiny language contains every feature of every language. Work through the foundations, then study the advanced topics in a real language such as JavaScript, Python, C, C++, Java, or C#.


STAGE 00
Computer & problem-solving basics
Hardware, CPU, memory, storage, operating systems, files and paths, terminal basics, binary, algorithms, pseudocode, flowcharts, decomposition, abstraction, debugging mindset.

Syntax is language-specific.

🥬 The C-to-Banana Engineering Curriculum
C CONCEPTS · BANANA EXPLANATIONS
Mission: learn the ideas taught in a serious C course, explained as if a sleep-deprived banana is teaching another banana beside a whiteboard that is on fire. The jokes are optional; the mental models are not.
Important honesty notice
The current browser interpreter is a real, hand-written lexer/parser/interpreter for its documented subset—not a C compiler and not yet a full implementation of this syllabus. A genuine C compiler also needs a much larger language implementation, runtime/toolchain, and platform-specific behavior. We will expand BananaScript feature-by-feature and clearly label what actually runs.


C UNIT 01
What a computer actually does
Bits, bytes, binary, hexadecimal, CPU, RAM, storage, instructions, machine code, source code, compiler, linker, executable, operating system, terminal, files, paths, environment and exit codes. Model: the CPU is an extremely fast clerk who follows instructions literally and has never once understood your vibes.


C UNIT 02
Translation: from banana scribble to machine action
Preprocessing, compilation, assembly, linking, loading, compilation vs interpretation, tokens, grammar, syntax errors, semantic errors, runtime errors, warnings, diagnostics, ASTs, symbol tables and compiler phases. A compiler is not a magical translator; it is a chain of picky departments.


C UNIT 03
Program anatomy and main
Program entry point, statements, expressions, blocks, declarations, definitions, headers, source files, translation units, comments, formatting, naming conventions and the build/run cycle.


C UNIT 04
Types, variables and constants
Character, integer, floating-point, Boolean concepts, signed/unsigned, widths, ranges, literals, identifiers, keywords, initialization, assignment, const, scope, lifetime, storage duration, type conversion, casts, overflow, precision and implementation-defined behavior.


C UNIT 05
Operators without summoning a math demon
Arithmetic, remainder, increment/decrement, relational, equality, logical AND/OR/NOT, bitwise operators, shifts, assignment operators, conditional operator, sizeof, precedence, associativity, short-circuiting, integer division and side effects.


C UNIT 06
Input, output and formatting
Standard input/output/error, printf-style formatting, format specifiers, escape sequences, reading input, whitespace, parsing text, validation, buffering, EOF and why blindly trusting input is how bugs get a company ID card.


C UNIT 07
Decisions and control flow
if, else-if, else, switch, case, default, fallthrough, conditional expressions, nested branches, truth values, compound conditions and control-flow diagrams.


C UNIT 08
Loops and loop discipline
while, do-while, for, nested loops, break, continue, loop counters, sentinel loops, off-by-one errors, infinite loops, invariants, termination and tracing. A loop is a worker who keeps doing the same task until you provide a condition that actually changes.


C UNIT 09
Functions: stop building one 900-line noodle
Declarations, prototypes, definitions, parameters, arguments, return types, void, return, pass-by-value, scope, local variables, recursion, call stack, stack frames, contracts, decomposition and function design.


C UNIT 10
Arrays and strings
Array declaration, initialization, indexing, bounds, traversal, multidimensional arrays, character arrays, null terminators, string literals, common string operations, buffer sizes, off-by-one errors and safe string handling.


C UNIT 11
Pointers: addresses are not values
Memory addresses, address-of (&), dereference (*), null pointers, pointer types, pointer arithmetic, arrays/pointers relationship, passing addresses, output parameters, const pointers, dangling pointers, wild pointers and why pointer bugs are not a personality test.


C UNIT 12
Memory layout and lifetime
Stack vs heap (conceptually), static storage, automatic storage, allocation, free, ownership conventions, leaks, double-free, use-after-free, alignment, object representation, sizeof, lifetime rules and undefined behavior.


C UNIT 13
Structures, unions, enums and aliases
struct, member access, nested structures, arrays of structures, typedef, enum, union, padding, alignment, tagged unions, representing records and choosing data layouts.


C UNIT 14
Preprocessor and headers
#include, #define, macros, function-like macros, conditional compilation, include guards, header/source separation, declarations vs definitions, macro hazards and why text substitution is not a type system.


C UNIT 15
Files and error handling
File streams, open/read/write/close, modes, text vs binary, checking return values, errno concepts, EOF, resource cleanup, error codes, defensive programming and robust failure paths.


C UNIT 16
Standard library and common tools
stdio, stdlib, string, math, ctype, stdbool, limits, fixed-width integer types, time basics, documentation lookup, library contracts and choosing standard functionality instead of inventing a cursed wheel.


C UNIT 17
Bits and low-level representation
Binary/hex conversion, masks, bitwise operations, shifts, flags, endianness, integer representation, signedness, bytes, character encoding, memory inspection and hardware-facing concepts.


C UNIT 18
Undefined behavior and portability
Undefined, unspecified and implementation-defined behavior; integer overflow concerns; uninitialized values; invalid memory access; sequence/evaluation concerns; portability; compiler assumptions and why “it worked once” is not a proof.


C UNIT 19
Data structures and algorithms in C
Complexity, arrays, linked lists, stacks, queues, hash tables, trees, heaps, graphs, searching, sorting, recursion, dynamic programming, allocation strategy and ownership-aware implementations.


C UNIT 20
Build systems, debugging and testing
Compiler flags, warnings, separate compilation, linking, Makefiles, debugger breakpoints, stepping, inspecting variables, sanitizers, static analysis, unit tests, assertions, reproducible builds and reading crash reports.


C UNIT 21
Advanced C territory
Function pointers, callbacks, variadic functions, qualifiers, volatile, restrict, atomics, threads, signals, setjmp/longjmp concepts, flexible array members, opaque types, ABI, calling conventions and version/standard differences.


C UNIT 22
Security and systems projects
Input bounds, integer overflow, format-string risks, buffer overflows, safe parsing, least privilege, file utilities, text parser, dynamic array, linked-list library, mini shell concepts, binary file reader and a final multi-file project.


How each topic will be taught
  1. Idiot explanation: the absurd analogy, followed by the exact technical definition.
  2. Trace it: predict the value of every important variable.
  3. Run it: use only syntax the current interpreter actually supports.
  4. Break it: trigger a common mistake and read the error.
  5. Build it: solve a small problem without copying the answer.
  6. Transfer it: compare the BananaScript idea with real C syntax and behavior.
Scope: this map covers the major topics in a comprehensive C learning path. C standards and compiler implementations have additional details; we will distinguish core language rules from platform-specific behavior rather than pretending one web page can contain the entire ISO C standard.
⌨️ Syntax reference: the shapes to recognize
BANANASCRIPT
BananaScript examples below use the language's primary syntax. The aliases are supported too, but learn one spelling at a time.
Optional aliases
stash = declare a variable · yell(...) = print · again N { ... } = repeat N times · when (...) { ... } otherwise { ... } = if/else. These aliases are real and runnable.
Comments
// A note for humans nyeet("Hi");
Values & variables
hoard name = "Mango";
hoard count = 4;
hoard ready = true;
Expressions
yeet(2 + 3 * 4);
yeet(count >= 2);
yeet("Hi " + name);
Decision
panic_if (count > 0) {
  yeet("In stock");
} cope_else {
  yeet("Sold out");
}
Repetition
loop_de_loop 3 {
  yeet("Again");
}
Assignment
hoard count = 4;
count = count + 1;
yeet(count);
Functions and arrays
recipe double(n) {
  send_back n * 2;
}
hoard fruits = ["banana", "mango"];
push(fruits, "pear");
yeet(double(len(fruits)));
yeet(fruits[1]);
BananaScript also supports while, arrays, indexing, functions, returns, and documented built-ins. See the language reference for exact limits and unsupported features.
